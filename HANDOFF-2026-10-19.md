For whoever (Claude Code or a person) continues on the **Linux** machine. The

## 0. Do this first: your Linux checkout is on the OLD history

GitHub's history was rewritten into a fresh public repository (same content,
new hashes, 25 Sep to 19 Oct). A checkout made before that no longer shares
history with `origin/main`, so `git pull` will produce a mess.

```sh
cd ~/lumenspar
git status                      # anything uncommitted you want to keep? make a patch first:
git diff > ~/lumenspar-old-uncommitted.patch
git fetch origin
git switch -c old-local-history # keeps the old commits reachable, just in case
git switch -C main origin/main  # now on the real main
git pull origin update-button   # or: git switch update-button (see section 2)
```

Nothing from the old local-only commits is lost: they exist on GitHub as the
rewritten equivalents (UTF-8 I/O, the clipping fix, rarity-coloured stars,
background AI batches, scroll-in-viewport fix, failure-log fix, the Windows
installer workflow).

## 1. Where the project is (version 0.3.3 released, 19 Oct)

Four tools on a main menu: **Wish Counter**, **Inventory Scanner**, **Build
Cards** (Enka.Network plus HoYoLAB for every character, CV | RV roll value),
**Optimizer** (best artifacts, team damage via Genshin Optimizer's own engine).

`.github/workflows/windows-release.yml` (PyInstaller + Inno Setup,

`packaging/linux/`). Both create the release as a **pre-release**. Version is
declared in `pyproject.toml`; the workflows check the tag against it.

The old handoff files (`docs/HANDOFF.md`, `docs/SESSION_HANDOFF.md`) are no
longer in the repo. The reasoning in them survives in code comments.

## 3. Windows facts worth knowing

- **Smart App Control blocks the installer for some people** ("An Application
  Control policy has blocked this file", code 4551). Cause: nothing is
  code-signed (`Lumenspar.exe`, `setup.exe` and ~29 third-party `.pyd` files;
  Qt's and Python's DLLs are already signed). Users can turn Smart App Control
  off, but Windows will not let them turn it back on, so this is not an
  acceptable instruction for the public. The real fix is signing: SignPath
  Foundation (free for open source, needs the GitHub Actions build), Azure
  Artifact Signing (~$10/month, individuals only in some countries), or an OV
  certificate. Untested whether Smart App Control accepts any valid signature.
  Decision pending with the user; not started.
- Windows build is AI-reader only (Gemini); a complete in-game inventory scan
  on Windows has not been confirmed end to end (live artifact scans have run).
- **Three artifacts were refused in a Windows scan** because the Traveler name
  was blank in the Windows settings: the bar said "Gal", which fuzzy-matches
  Albedo at 72, under the 78 floor. Fix is a settings entry (Traveler `Gal`,
  Wanderer `HatGirl`), not code. Do not also list `Gal1` under "Other renamed
  characters": with both, every read of either name is refused by design.
- Store Python virtualises AppData: the dev venv writes settings under
  `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation...\LocalCache\Roaming\lumenspar\`.
  A real install uses `%APPDATA%\lumenspar`. Settings do not carry over.
- Long paths overflow `MAX_PATH` under Store Python (use short temp dirs).

## 4. Things learned the hard way (this session)

- **Windows opens text files as cp1252.** Every text read/write must pass
  `encoding="utf-8"`. A blanket `except` in `_save_failure` hid this for days
  (empty `failures.txt`, no screenshots). Fixed on main; keep it that way.
- AI-mode navigation reads (header, tab title) are Gemini round trips of 4-14 s
  each on the free tier; the scanner passes the first header reading on rather
  than re-reading it.
- Qt's `QJSEngine` has no `async`/`await`. To test page JavaScript, run it in
  real Chromium through `QWebEnginePage` offscreen with a fake `fetch`
  (see how the HoYoLAB script was tested). There is no Node on the Windows box.
- `Settings` is a slotted dataclass: patch `Settings.save` on the class in tests.
- PyInstaller: a one-folder build, never `--onefile` (slow start, antivirus).
- GitHub's API digest, `/releases/latest` and pre-releases: see section 2.

## 5. Linux-specific open items (from earlier sessions, still true)

- Linux Escape watcher: "could not watch for Escape; use the Stop button"; the
  user cannot read `/dev/input/event*` (group membership needs `sudo`; hand the
  user the command).
- `/var/home/gal/.git` is an accidental empty repo in the home directory
  (`rm -rf ~/.git` if unwanted).
- Gal vs Gal1 guard, Manekins that cannot be keyed, sub-1080p talent reads,
  Genshin Optimizer lagging new content: unchanged.
- The failure corpus (`~/Documents/Lumenspar/failures/`, ~1.1 GB) exists only on
  the Linux machine; AI-mode accuracy on it has never been measured.
  `tools/ai_eval.py` runs the AI reader over saved screenshots.
